# 03 — 记忆上下文 详细文档

> 对应技能：`.codebuddy/skills/03-memory-context/SKILL.md`

## 问题场景

AI 编程助手的"失忆症"表现为：

1. **/clear 之后**：所有上下文清空，AI 问"你想做什么？"
2. **长对话末尾**：前面的决策被 token 截断
3. **多会话并行**：两个会话处理同一项目但互不知情
4. **知识遗失**：某个 bug 的根因分析结果，下次还需要重新分析

## 解决方案总览

四文件记忆系统通过**文件持久化**解决以上所有问题：

```
每个编码会话的生命周期：

会话开始 ──→ 读取记忆文件 ──→ 恢复上下文
    │
编码过程 ──→ 发现新信息 ──→ 追加到 findings.md
    │        做出决策     ──→ 记录到 decisions.md
    │
完成子任务 ──→ 更新 progress.md
    │
会话结束 ──→ 刷新所有记忆文件
```

## 记忆文件位置

```
your-project/
└── .codebuddy/
    └── memory/           ← AI 自动创建和维护
        ├── task_plan.md
        ├── findings.md
        ├── progress.md
        └── decisions.md
```

## 各文件的维护规则

### task_plan.md — 何时更新

| 事件 | 操作 |
|------|------|
| 新任务开始 | 创建/更新任务列表 |
| 子任务完成 | 勾选 `[x]`，记录完成时间 |
| 计划变更 | 更新任务描述，记录变更原因 |
| 任务完成 | 整个文件归档到 `memory/archive/` |

### findings.md — 何时追加

| 事件 | 追加内容 |
|------|----------|
| 发现项目入口文件 | 记录文件路径和作用 |
| 理解了一个模块 | 记录模块结构和关键导出 |
| 发现依赖关系 | 记录依赖图 |
| 遇到坑点 | 记录问题和解决方案 |
| 发现代码模式 | 记录模式和使用频率 |

### progress.md — 会话粒度

每个 AI 会话结束时更新：

```markdown
| 会话 #3 | 2026-07-03 12:30 | 完成 Token 存储 + 状态管理 | ~8000 tokens | ✅ |
```

### decisions.md — ADR 格式

采用轻量级 ADR（Architecture Decision Record）：

```markdown
## DEC-003：使用 Context 而非 Props Drilling
- 状态：已采纳
- 原因：组件层级 >4 层，props 传递已不可维护
- 替代方案：Redux（过重）、Jotai（团队不熟悉）
```

## 记忆恢复演示

```
用户：继续上次的任务

AI：（自动读取 memory/）
    📋 上次任务：实现用户登录 [#2 会话]
    📊 当前进度：
      ✅ API 登录接口
      ✅ 登录表单 UI
      ⬜ Token 存储    ← 下一步
    🧠 已知信息：
      - 使用 Zustand 状态管理 (DEC-001)
      - 后端返回 { token, user } 格式
      - useAuth 不能在 Router 外层用
    
    准备好了，开始实现 Token 存储？
```
