# Andrej Karpathy 的 AI 编码指南

> 来源：https://github.com/multica-ai/andrej-karpathy-skills
>
> 这是 Karpathy 观察 LLM 编码缺陷后总结的行为准则，作为 SJKNCS 代码优化维度的理论基础。

## 核心理念

### 1. 先思考再编码（Think Before Coding）

在写任何代码之前：
- 明确陈述你的假设
- 呈现对问题多种可能的解释
- 如果你不确定或有困惑，停下来提问，不要猜测
- 将模糊的任务转化为清晰、可验证的目标

```
反例："好的，我来重构这个组件。"（没有给出你理解的问题）
正例："分析后发现 3 个问题：1) 长函数 120 行 2) 重复的 fetch 逻辑 3) 硬编码 URL。
      我的方案是：提取 renderChart()、创建 useFetch hook、提取 API_BASE_URL 常量。
      这些理解对吗？"
```

### 2. 简单优先（Simplicity First）

- 用最少的代码完成工作
- 不要过度抽象（一个简单组件不需要 5 层继承）
- 不要添加未被要求的功能
- 如果可以用 3 行解决，不要写 30 行

```
反例：为一个 3 字段的表单创建了 GenericFormBuilder<T> 泛型抽象层
正例：直接写一个带 3 个 input 的简单表单组件
```

### 3. 精准修改（Surgical Changes）

- 只修改必须改的部分
- 匹配项目现有的代码风格和模式
- 不要"顺手优化"无关代码
- 不要重新格式化你未修改的代码
- 不要改变未明确要求修改的函数签名

```
反例："顺便把整个文件的 var 改成了 const"（范围蔓延）
正例：只改目标函数体内的逻辑，保持接口不变
```

### 4. 目标驱动执行（Goal-Driven Execution）

- 将任务转化为可逐步验证的目标
- 定义每一步的成功标准
- 只在前一步验证通过后才进行下一步
- 迭代直到所有目标都验证通过

```
任务：添加用户登录
├── 目标 1：创建 API 登录端点 → curl 测试返回 200 + token
├── 目标 2：前端登录表单 → 输入凭证后看到 token 存储
├── 目标 3：登录状态持久化 → 刷新页面仍保持登录
└── 目标 4：错误处理 → 错误凭证显示提示消息
```

## 实践建议

1. **每个 commit 只做一件事** — 便于 review 和回滚
2. **先写测试（至少先想好怎么测）** — 验证修改是否正确
3. **代码是写给人看的** — 命名比注释重要，清晰比聪明重要
4. **怀疑你的第一直觉** — 停下来想一想有没有更简单的方法
