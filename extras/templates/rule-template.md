# 规则模板

将此模板复制到对应目录即可创建新规则。

---

## 标准规则模板

```markdown
---
rule_id: RULE-XXX          # 唯一标识
version: 1.0.0
priority: medium           # high | medium | low
scope: project             # project | user | team
applies_to: always         # always | manual | pattern
patterns: ["*.ts", "*.tsx"]  # 仅 applies_to=pattern 时需要
conflicts_with: []         # 与哪些规则冲突
supersedes: []             # 替代哪些旧规则
created: 2026-07-03
updated: 2026-07-03
---

# [规则名称]

## 目的
[1-2 句话说明此规则解决什么问题]

## 适用场景
[何时触发此规则]

## 行为约束

### 必须执行
1. [强制性要求]
2. [强制性要求]

### 禁止
1. [禁止行为]
2. [禁止行为]

### 建议
1. [推荐做法]
2. [推荐做法]

## 示例

### ✅ 正确做法
```code
// 好的代码示例
```

### ❌ 错误做法
```code
// 不好的代码示例
```

## 例外情况
[何时可以违反此规则，以及替代方案]

## 来源/参考
[此规则的来源、灵感或相关链接]
```

## 规则优先级速查

| 优先级 | 含义 | 示例 |
|--------|------|------|
| **high** | 必须遵守，违反会导致严重问题 | 安全规则、数据完整性规则 |
| **medium** | 强烈建议遵守，特殊情况可豁免 | 代码风格、命名规范 |
| **low** | 推荐但不强制 | 注释风格、文件组织偏好 |

## 规则命名规范

规则 ID 格式：`RULE-{分类}-{序号}`

| 分类 | 前缀 | 说明 |
|------|------|------|
| 安全 | RULE-SEC | SQL 注入防护、XSS 防护等 |
| 风格 | RULE-STY | 命名规范、格式化等 |
| 架构 | RULE-ARC | 模块划分、依赖方向等 |
| 性能 | RULE-PER | 缓存策略、查询优化等 |
| 测试 | RULE-TST | 测试覆盖率、测试模式等 |
| 流程 | RULE-PRC | Git 工作流、Code Review 等 |
